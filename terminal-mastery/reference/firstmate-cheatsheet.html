Firstmate

You talk to one agent in plain English. This page is what to say, what it means, and how to check the work yourself.

Start it

gh auth login
git clone https://github.com/kunchenguid/firstmate
cd firstmate
cc              # your alias for claude --dangerously-skip-permissions

There is no binary. The clone is the product: launching an agent inside it makes that agent the first mate. Claude, Grok and Pi are the three recommended harnesses; Codex, OpenCode, Cursor and Kimi also work.

The five slash commands

/bearingscold start. Live fleet digest.
/ahoywarm return. Recap this session + open decisions.
/afkstepping away. Batches escalations.
/stowsave knowledge before a context reset.
/updatefirstmatepull latest, fast-forward only.

Bearings modes: /bearings file also writes a dated report, /bearings lavish also builds an interactive board, and include PRs composes with either.

Codex uses $ instead of /: $afk.

What to say

"fix / add / implement X"a ship task → PR or merged branch
"investigate / audit / plan X"a scout task → a report, never a PR
"merge it"the only thing that authorises a merge
"show me the diff for X"it runs the review script for you
"put X on direct-PR with yolo on"sets the standing posture for a project
"set up a secondmate that owns X"creates a persistent second mate

A report may recommend an implementation. It never authorises one - you still say "do it".

Roles

captainyou. only human. only merge authority.
first matethe one agent you talk to. never edits projects.
crewmatedisposable, one task, own worktree, own tab.
secondmatepersistent, own isolated home + charter, local or SSH.

Neither crewmates nor secondmates ever speak to you directly.

Delivery modes

no-mistakesfull pipeline: review, tests, lint, docs, PR, CI green. Default.
direct-PRpush and open a PR, no pipeline
local-onlyclean local branch, no remote
+ yolomerge authority only. Green and in-scope only. Never red.

Mode and yolo are independent. An unregistered project defaults to no-mistakes, yolo off.

Check the work yourself

bin/fm-review-diff.sh <id> --stat   # shape first
bin/fm-review-diff.sh <id>          # full diff vs base
bin/fm-peek.sh <id> [lines]         # tail a worker's terminal
bin/fm-crew-state.sh <id>           # one authoritative status line
bin/fm-fleet-view.sh                # whole fleet, readable
bin/fm-fleet-snapshot.sh            # same, as JSON

fm-review-diff.sh fetches the live PR head when a PR exists, so you always see current code after fix rounds - never a stale snapshot.

The review loop

  1. It reports a PR with the full URL.
  2. bin/fm-review-diff.sh <id> --stat - is the shape sane?
  3. gh pr checkout 42, then nvim and :DiffviewOpen main...HEAD.
  4. Tab through every file. Chase symbols with *.
  5. "merge it", or say what is wrong in plain English.

Watch it live

Every crewmate is a real Herdr tab:

Right ⌘ bsidebar - who is working / blocked / done
Right ⌘ gfuzzy-jump to a worker's tab
Right ⌘ zzoom it full-screen to read

You can type into a worker's tab. The first mate treats that as authoritative and reconciles it at its next check.

Hard rules that protect you

  1. Never writes to a project. Crewmates do, in worktrees.
  2. Never merges without your explicit word (or standing yolo).
  3. Never tears down unlanded work. A refusal means stop and look.
  4. Crewmates never address you.
  5. Reports outcomes faithfully, including failures.

When it reaches you

Exactly six things:

  • Work ready for review, with the full URL
  • Finished investigation findings
  • A decision it cannot make
  • A real blocker or failure
  • Anything destructive, irreversible, or security-sensitive
  • A credential or login it needs

Silence is healthy. Elapsed time and "still working" are deliberately not reported.

Config you might set

echo herdr > config/backend
echo codex > config/crew-harness
echo off   > config/herdr-presentation-spaces
backendtmux (verified), herdr / cmux (auto-detectable), zellij / orca (explicit)
crew-harnesswhich agent crewmates run
secondmate-harnesswhich agent secondmates run
herdr-presentation-spacesoff for a flat tab layout instead of one workspace per task

All gitignored and local. Backend auto-detects: inside Herdr and not inside tmux means crewmates go to Herdr.

Secondmate - when

Yes: a genuinely standing domain ("the mobile app", "everything on that box"), or work that must run on another machine.

No: a handful of tasks. Ordinary crewmates are free and disposable; a secondmate is a persistent home with state to keep converged.

Remote secondmates always run on Herdr - no choice. Secondmates never spawn secondmates. Never hand-edit data/secondmates.md; ask the first mate.
